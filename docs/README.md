# Knowledge Base

이 `docs/` 디렉터리는 **프로젝트 코드 구조를 미러링**한다.
특정 코드 작업 전, 해당 경로의 md 파일을 참고한다.

## 제품 비전

**스마트 AI GitHub 레포 블로그 에디터**

개발자가 GitHub 레포를 연결해두면, AI 에이전트가 해당 레포의 파일시스템을
직접 탐색하며 블로그 글 작성을 함께 도와주는 서비스.

### 핵심 유저 플로우

```
1. 새 글 작성 버튼
      └→ 제목 입력 + GitHub 레포 선택
             └→ 에디터 페이지
                  ├── 왼쪽: 마크다운 에디터 (직접 작성)
                  ├── 오른쪽: AI 에이전트 챗
                  └── 상단/사이드: 연결된 레포 기본 정보

2. 에이전트가 할 수 있는 것
      ├── 일반 질문 답변 (글쓰기 방향, 구조 제안 등)
      ├── 에디터 글 수정 (수정 제안 → 적용 버튼)
      └── 레포 파일 탐색 후 컨텍스트 기반 답변
           (list_directory → read_file → search_in_repo)
```

### 핵심 차별점
- LLM 요약 방식 아님 — 에이전트가 파일시스템을 직접 탐색
- 에이전트가 에디터 내용을 알고 있음 (매 요청마다 주입)
- 수정 제안은 사용자 승인 후 반영 (Human-in-the-loop)

## 파일 작성 규칙
- 코드 디렉터리가 생기면 대응하는 docs 파일도 함께 만든다
- **"왜"** 중심으로 작성한다 (what은 코드가 설명한다)
- 결정이 바뀌면 `docs/adr/` 에 기록한다
