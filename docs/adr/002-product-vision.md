# ADR 002: 핵심 제품 비전 확정

## 날짜
2026-05-23

## 상태
결정됨

## 배경
초기 기획에서 "GitHub 레포를 참조해 블로그를 쓴다"는 방향은 있었으나,
에이전트의 역할과 유저 플로우가 구체적으로 정의되지 않았다.
1주차 설계 이후 핵심 UX와 에이전트 역할을 다음과 같이 확정한다.

## 결정

### 제품 정의
**스마트 AI GitHub 레포 블로그 에디터**
- 개발자가 GitHub 레포를 연결하면 AI가 해당 코드베이스를 이해하고
  블로그 글 작성을 함께 도와주는 서비스

### 핵심 유저 플로우
1. 새 글 작성 → 제목 + GitHub 레포 선택
2. 에디터 페이지: 마크다운 에디터 + AI 챗 + 레포 기본 정보
3. AI 에이전트가 할 수 있는 것:
   - 일반 질문 답변 (글 방향, 구조 제안)
   - 에디터 글 수정 제안 (사용자 승인 후 반영)
   - 연결된 레포 파일 탐색 후 컨텍스트 기반 답변

### 에이전트 설계 원칙
- **Human-in-the-loop**: 에디터 직접 수정 없음, 제안 → 승인 → 반영
- **파일시스템 직접 탐색**: RAG 없음, 에이전트가 필요한 파일을 골라 읽음
- **포스트 컨텍스트 주입**: 매 챗 요청마다 현재 에디터 내용 전달

### 포스트-레포 관계
- 포스트 1개 ↔ 레포 1개 (생성 시 선택, 이후 변경 가능)
- 레포는 서버에 git clone 후 파일시스템으로 탐색
- 브랜치는 챗 세션 내에서 에이전트가 필요 시 탐색

## 대안 검토
- **RAG 방식**: 벡터 DB에 레포 인덱싱 후 검색
  → 탐색 유연성이 낮고 구현 복잡도가 높아 제외
- **레포 여러 개 연결**: 복잡도 증가 대비 UX 이점 불명확 → 1개로 단순화
- **에이전트 직접 편집**: 사용자 의도와 다른 수정이 될 수 있어 제외
